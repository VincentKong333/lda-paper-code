## 2. 七套标准流程

### S0 环境准备（一次性，5 分钟）

```bash
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install lifelines jieba scikit-learn pandas matplotlib openpyxl
python3 check_env.py        # 期望 6/6 通过
```

**通过标准**：Python≥3.7、零第三方依赖（采集侧）、签名有效、列表与详情接口各返回 1 条。
**耗时**：约 10 秒（2 个请求）。

### S1 可采范围探测（换周期/首次接触时必须，16 分钟）

```bash
python3 probe_window.py     # 只读，刷新 13 个 list 缓存
```

**产物**：`window_probe_YYYYMMDD.json`（每板块条数/最早/最新）+ `list_<fid>.json`。
**通过标准**：13 板块最早日期一致（证明窗口机制），无 403。
**注意**：这一步会覆盖旧 list 缓存，脚本已自动备份到 `backup_pre_probe/`。

### S2 零网络预检（每次改窗口必跑，3 秒）

```bash
# 先改 config.py 的 WINDOW_START_TS / WINDOW_END_TS / OUT_NAME
python3 preflight_window.py
```

**产物**：`preflight_YYYYMMDD.json`（窗内/窗外逐板块条数 + 耗时估算）。
**通过标准**：窗内条数与预期一致；`OUT` 文件为全新（决定是增量还是全量重采）。

### S3 采集（长跑，约 17 小时）

```bash
# Windows
python3 -u run_scraper_win.py
# Mac
./start.sh            # 停止: ./stop.sh
```

**产物**：`collected_<name>.jsonl`（逐条 flush，可断点续跑）。
**通过标准**：日志零 `403/退避/Traceback`；条数逐板块与 S2 预检吻合。

### S4 质检（1 分钟）

```bash
python3 - <<'EOF'
import json,collections
rows=[json.loads(l) for l in open('collected_all13_20260914.jsonl',encoding='utf-8') if l.strip()]
tids=collections.Counter(str(r['tid']) for r in rows)
print('总条数',len(rows),'| 唯一tid',len(tids),'| 重复',sum(1 for v in tids.values() if v>1))
print('板块分布',dict(sorted(collections.Counter(r['fid'] for r in rows).items())))
print('时间范围',min(r['create_date'] for r in rows),'~',max(r['create_date'] for r in rows))
print('空正文',sum(1 for r in rows if not (r.get('content') or '').strip()),
      '| 无回复',sum(1 for r in rows if not r.get('reply_dateline')))
EOF
```

**通过标准**：零重复、13 板块条数与预检逐一吻合、窗外 0、空正文 0、无回复率合理（10% 左右）。

### S5 内容分析 LDA（主研究，约 3~5 分钟）

```bash
python3 content_lda.py --input collected_all13_20260914.jsonl \
  --kmin 6 --kmax 18 --kstep 2 --min-df 5 --topn 15
```

**产物**：`results/LDA内容分析报告.md`、`lda_topics.csv`、`lda_k_selection.csv`、
`lda_doc_topic.csv`、`lda_topic_by_{board,type,domain,year}.csv`。
**通过标准**：UMass 一致性曲线有明确最优点；主题词可人工命名；效度验证倍数≥2 且 n≥100。

### S6 生存分析（辅助，约 20 秒）

```bash
python3 survival_cox.py --input collected_all13_20260914.jsonl --censor "2026-09-15 06:42:00"
```

**产物**：`results/生存分析报告.md`、`生存分析_*.csv`、`fig_KM曲线.png`、`fig_Cox森林图.png`。
**通过标准**：Concordance 0.7 以上；队列稳健性表中"随访不足"的季度已标注。

### S7 导出与报告（1 分钟）

```bash
python3 export_excel.py     # → results/全字段数据表_*.xlsx
```

Word 技术报告走 `tencent-docx` 流水线（Stage1 写作 → Stage2 排版 HTML → Stage3 转 docx）。

## 3. 三个必须先拍板的决策

| 决策 | 本次选择 | 理由 |
|---|---|---|
| 主窗口 | 2024-10-01 ~ 2026-08-31 | 23 个完整自然月，首尾不是残月；接口硬底还有 17 天缓冲 |
| 时延口径 | 生存分析（不截断） | 朴素口径只用已回复样本，中位时延低估 17.4% |
| 快照 | 全量重采统一时刻 | 旧数据分多次采完，每条删失时刻不一，生存分析不成立 |

**增量 vs 全量判断**：`OUT_NAME` 指向的文件为空 = 全量重采；文件已有数据 = 只补新增。
配套：删 `list_<fid>.json` 才会重拉列表；保留 jsonl 才能跳过已采。

## 4. 十条坑（按踩到的频率排序）

1. 列表接口**必须** `showUnAnswer=1`，否则漏掉全部未回复留言（约 20%）。
2. `crawl_list()` 见 list 缓存非空就跳过列表阶段 —— 增量只删缓存、不删数据。
3. `OUT_NAME` 是"已采判断"的唯一依据，改名 = 从头采。
4. 窗口过滤在**取详情之前**，窗外记录不发请求（省时）。
5. 站点是**滚动近两年**窗口，每天前移一天，越晚采越少。
6. Cox 里年份**必须作分类变量**（90 天回复率是 U 形，不是单调）。
7. HR>1 = 回复**更快**，方向别写反。
8. LDA 效度表要带样本量，小样本（n<100）的倍数不可引用。
9. Excel 导出前要清非法控制字符（`\x0b` 等），`export_excel.py` 已内置。
10. 停用词表是 3 轮迭代出来的，别清空重来；噪音词按文件第 7 节分组维护。

## 6. 换机器迁移

完整迁移包见 `liuyan_migration_20260915.zip`（含数据、代码、产物、MD5 清单）；
Mac 端重建顺序见包内 `MIGRATION_README.md` 第五节。核心差异：

- Mac 用 `start.sh` / `stop.sh`（caffeinate 防休眠），Windows 用 `run_scraper_win.py`（ctypes 防休眠）。
- `config.py` 的时间戳按 CST 计算，Mac 同为 UTC+8，无需改。
- 采集脚本零第三方依赖；分析侧需 6 个 pip 包。
