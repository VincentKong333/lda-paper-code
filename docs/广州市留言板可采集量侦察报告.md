# 人民网领导留言板·广州市 可采集数据量侦察报告

> 侦察时间:2026-08-21
> 目的:确认广州市留言板接口"到底能翻到多少条"、以及"只能查近两年"是否属实
> 方式:纯 Python 直连 `POST /v1/threads/list/df`(签名已逆向),游标翻页至接口返回空,**仅计数、不存正文**

## 一、核心结论

1. **"只能查近两年"属实。** 13 个板块翻到的最早日期**全部卡在 2024-08-21**,没有任何一条 2021–2023 的记录。接口本身不返回更早数据。
2. **广州市实际可采集总量:9,843 条**(2024-08-21 ~ 2026-08-19,全部类型)。
3. **与开题报告原计划(2021/1–2025/12 全量)的差距:**
   - 2021–2023 数据接口不返回 → 原计划中这 3 年**拿不到任何数据**;
   - 落在"2021-01-01 ~ 2025-12-31"窗口内的实际可得 **7,904 条**(2024-08-21 至 2025-12-31);
   - 另有 1,939 条来自 2026 年(超出原窗口,但属于"近两年"切片)。

## 三、反爬实测与节奏

- 原定列表请求间隔 3.5s:实测约 8 个请求后被服务器 **403 限流**(仅 `/v1/` API 路径,首页/列表页 HTML 不受影响,属"短窗口请求数过多"型限流)。
- 本次侦察改用**列表请求间隔 9 秒 + 抖动 + 每 10 次额外冷却**,全程未再触发 403,13 板块 80 页约 14 分钟跑完。
- 建议正式采集:列表间隔 ≥ 8–9s;详情页(`/v1/threads/content`)间隔 4–6s(用户要求),两者叠加更稳。

## 四、对开题报告的影响建议

- 数据时间窗需从"2021/1–2025/12"调整为**"2024-08–2025-12"**(可得 7,904 条)或**"2024-08–采集当日"**(可得 9,843 条);
- 既定语料规模(原计划"约 4–5 万条"的全市 5 年)需下调,LDA 主题建模与回复时延分析在 8 千–1 万条量级仍完全可行;
- 字段可得性:列表接口已含 标题/时间/主题分类/状态/摘要;回复正文/回复部门/回复时间/评价状态需再进详情页(`/v1/threads/content`)——该接口签名同法可用。

## 五、技术注记(供后续正式采集复用)

- 列表接口:`POST /v1/threads/list/df`,param=`{fid, showUnAnswer:1, lastItem, position:0, rows:200, orderType:2}`,**游标分页**(下一页带上一页末条 `tid`);`rows` 最大 200。
- 详情接口:`POST /v1/threads/content`,param=`{tid}`。
- 签名:`md5(接口路径 + JSON(param) + appSecret + token)`,appSecret=`a2eb17bf...`(见脚本常量),token 未登录为空。
- 脚本位置:`liuyan_scraper/count_all.py`(计数)、`scraper.py`(采集骨架,待正式运行)。
