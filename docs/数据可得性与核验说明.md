# 数据可得性与核验说明

> 本仓库**不包含留言原文**。这不是数据缺失，而是刻意的隐私处理。
> 本文说明：仓库里保留了什么、为什么这样取舍、审阅者如何在不见原文的前提下验证数据真实可复现。

---

## 1. 为什么不留原文

| 原因 | 说明 |
|---|---|
| 隐私 | 留言正文是市民个人陈述，常含住址、门牌、电话、就医与家庭细节，即使平台已对昵称脱敏，正文本身仍可反向识别当事人 |
| 学术伦理 | 研究用途不构成再传播授权；论文引用需匿名化，批量公开原文与之相悖 |
| 平台规范 | 采集基于公开页面，但"可访问"不等于"可转载"；集中转载会放大原文的可检索性 |
| 无必要 | 复核研究方法与结论，依赖的是**数据规模、字段结构、统计口径与代码**，而非逐条原文 |

因此仓库采用「**代码 + 聚合结果 + 数据指纹**」的组合，替代「原始语料公开」。

## 3. 三档核验方式

审阅者可按需选择深度，三档都不需要看到原文。

### 第一档 · 文件指纹（10 秒）

确认你手上的数据与产出结果的版本是同一份文件：

```bash
sha256sum -c checksums.sha256
```

`checksums.sha256` 收录了主数据、13 个板块列表缓存与全字段 Excel 的哈希。
主数据基准值：

```
collected_all13_20260914.jsonl
SHA-256: 64c623b2b9885c256f4ee278b7576d2f94c44d220ed215fab9ed353845099bda
大小:    18,290,884 字节
```

### 第二档 · 统计基线（1 分钟）

不看原文，直接重算统计量并与公开基线逐项比对：

```bash
python tools/verify_dataset.py --input collected_all13_20260914.jsonl
```

脚本只读取数值字段，输出形如：

```
检查项                基线                  实际                  结论
总条数                10182                 10182                 OK
唯一 tid 数            10182                 10182                 OK
重复 tid 数            0                     0                     OK
最早留言时间           2024-10-01 08:40:32   2024-10-01 08:40:32   OK
最晚留言时间           2026-08-31 21:13:59   2026-08-31 21:13:59   OK
窗外条数(应为 0)        0                     0                     OK
有回复条数             9178                  9178                  OK
回复率(%)              90.14                 90.14                 OK
回复时延中位数(天)      39.05                 39.05                 OK
板块分布               13 个板块              13 个板块               OK
```

基线文件为 [`数据基线.json`](数据基线.json)，包含 13 个板块的逐板块条数、8 个关键字段的缺失计数与上述指标。

### 第三档 · 端到端复现（约 1 小时，需自备数据）

在原始数据就位后重跑分析与质检：

```bash
python tools/analyze.py    --input collected_all13_20260914.jsonl   # 质量报告
python content_lda.py      --input collected_all13_20260914.jsonl   # LDA（K=6）
python survival_cox.py     --input collected_all13_20260914.jsonl --censor "2026-09-14"
python export_excel.py                                              # 全字段 Excel
```

产出应与 `results/` 下已提交的文件一致（主题数、主题占比、Cox 系数、Concordance 0.745）。

## 4. 为什么保留 `tid`

`results/lda_doc_topic.csv` 保留了 `tid`（留言编号）、板块、时间、主题编号与主题概率，但**不含任何文本**。

保留理由：
- `tid` 是人民网留言板页面上公开可检索的帖子编号，本身就是公开信息；
- 它让审阅者可以**随机抽 20 条到站内核对**「这条记录确实存在、时间与板块对得上」，这是验证"非编造"最直接的手段；
- 同时不暴露内容本身——核对哪一条由审阅者自行决定，仓库不主动散发。

如认为 `tid` 也不宜公开，可在本地删除该列后再发布，分析结论不受影响。

## 6. 审计可复现

第 2 节所述"仓库无原文"的结论可用同样方法复验：

1. 读取本地 jsonl，对 `content / subject / nick_name / reply_content / reply_nick_name` 每个非空值取前 12 个字符（去空白）作为指纹，得到指纹集合；
2. 遍历仓库内全部文本与 `.docx` 文件，去掉空白后滑窗取 12 字符，与指纹集合比对；
3. 命中数应为 0。

该检查不保存、不输出原文，仅统计命中次数。
